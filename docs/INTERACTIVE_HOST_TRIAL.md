## 2026-11-23 本地验证

在隔离的日期示例仓库中，测试程序扮演终端用户。讨论、实施与审查使用本地构造的模型响应，实际写入和只读测试由 Docker 执行。暂缓、重开、验收与核对验收回执均通过新启动的 Node 进程读取持久记录。重开路径没有加载模型凭据。[测试代码](../tests/chat-demo-execution.test.mjs)

| 场景 | 观察结果 |
|---|---|
| 正常验收 | 在 worktree 试跑，2024-04-30 输出 `valid`，2024-04-31 输出 `invalid date` 且退出码为 1。暂缓后重开仍显示同一任务、批准版本、worktree 和原因。带理由确认后进入 `DONE`，再次重开能看到原理由、R3 ID 和两项证据。验收前后均为 3 次 Agent 运行和 2 次工具操作。 |
| 验收授权 | 提前确认或省略理由时无法完成验收。重复确认返回原回执，审计只有一次人工验收。 |
| 测试与证据失效 | Docker 测试失败时任务停在 `BLOCKED`。已测试文件在 R3 或待人工验收期间被编辑时，成功验收被拒绝。恢复到原测试内容后可确认。 |
| 越界候选 | 候选要求改动未授权的 `README.md` 时，显示变更提议，工具调用为 0，工作区无该文件。 |
| 未对账的模型运行 | 模型派发后断线时显示 `RECONCILIATION_REQUIRED` 和运行 ID。重开后可查到相同 ID，再次输入 `/run` 未重发。 |
