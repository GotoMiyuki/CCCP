## 2. 本期摘要

在 macOS 复测中，Adapter 的 Discovery 会返回规范化后的 `/private/var/...` 临时目录，而 Project Profile 保留 `/var/...`，导致同一仓库被错误判定为不匹配。仓库路径比较现会解析已有路径的真实路径后再比较。新增符号链接仓库别名回归用例；不涉及协议语义或依赖变动。

---

## 3. 核心内容详解

### 3.1 架构与设计决策

- **流程/状态机**：不变。仅调整 Execution Lifecycle 对同一仓库路径别名的身份判断。
- **接口/模块边界约定**：Discovery 仍负责产生真实仓库路径；Lifecycle 只消费该结果并进行规范化比较。

### 3.2 关键代码实现详解

**改动点 A：`repositoryIdentity`**

- **意图**：将现有目录的词法路径转换为真实路径，避免 macOS `/var` 与 `/private/var` 别名造成误判。
- **关键代码**：
  ```js
  const repositoryIdentity = path => {
    const absolute = resolve(path);
    try { return realpathSync.native?.(absolute) ?? realpathSync(absolute); }
    catch (error) { if (error.code === 'ENOENT') return absolute; throw error; }
  };
  ```
